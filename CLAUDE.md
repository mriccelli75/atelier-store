## Next.js version warning

This project runs **Next.js 16.4 / React 19.3**, which is newer than most training data. Before writing Next.js code, check the bundled docs in `node_modules/next/dist/docs/` (`01-app/`, `03-architecture/`, etc.) rather than relying on memory, and heed deprecation notices. `AGENTS.md` is regenerated by `next dev`; don't remove it.

`next.config.ts` turns on `cacheComponents` and `partialPrefetching`, so caching and data fetching follow the Cache Components model (`"use cache"`, Suspense boundaries for dynamic data) rather than the older `fetch`-cache/`revalidate` conventions. Tailwind v4 runs through the `@tailwindcss/turbopack` loader configured there, not PostCSS.

## Commands

```bash
npm run dev          # dev server on http://localhost:3000 (Turbopack)
npm run build        # production build (also type-checks)
npm run lint         # ESLint 9 flat config (eslint.config.mjs)

npm run db:generate  # generate SQL migrations from src/db/schema.ts into ./drizzle
npm run db:migrate   # apply migrations
npm run db:push      # push schema straight to the DB (no migration files)
npm run db:studio    # Drizzle Studio
npm run db:seed      # upsert sample categories/products from src/db/seed-data.ts (idempotent)
```

No test runner is configured yet.

Copy `.env.example` to `.env` and fill in `DATABASE_URL` (Neon Postgres), `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`, and the Stripe keys (see Checkout below).

## Architecture

- **Database:** Neon serverless Postgres via Drizzle ORM using the HTTP driver (`drizzle-orm/neon-http`). The `db` client lives in `src/db/index.ts`; all tables go in `src/db/schema.ts`, the single schema file `drizzle.config.ts` points at. The neon-http driver doesn't support interactive transactions.
- **Auth:** Better Auth. The server instance in `src/lib/auth.ts` uses the Drizzle adapter (`provider: "pg"`) and is mounted at `/api/auth/*` by the catch-all route `src/app/api/auth/[...all]/route.ts`. Client-side code uses `authClient` from `src/lib/auth-client.ts` (`better-auth/react`).
- **Catalog data:** `src/db/schema.ts` has `categories` and `products` (one category → many products). Stock is `products.stock_quantity`; the status shown to customers is derived from it by `stockStatus()` in `src/lib/products.ts` (0 = sold out, ≤ `LOW_STOCK_THRESHOLD` = "Only N left"). Prices are integer cents. `products.department` (`women` | `men` | `unisex`) assigns a product to a shop section; unisex products appear in every section. `images` and `sizes` are jsonb (sizes are a plain list with an `available` flag, not variants). Migrations are generated into `./drizzle` and committed; use `db:generate` + `db:migrate`, not `db:push`.
- **Data access:** pages read through the cached, server-only functions in `src/db/queries.ts` (`"use cache"`, `cacheLife("hours")`, tag `"products"`), which map rows to the `Product` type. `src/lib/products.ts` holds only types and pure helpers, so client components can import it. Builds query the DB (`generateStaticParams`), so `DATABASE_URL` must be set and the DB seeded at build time.
- **Auth tables:** user/session/account/verification live in `schema.ts` (generated by `npx auth generate`, pasted in; regenerate after adding plugins). `auth.ts` enables email + password, uses `nextCookies()`, and has an `after` hook that merges the guest bag into the user's bag on sign-in/up and clears the `bag` cookie on sign-out. `/account` is the sign-in/sign-up page and order history.
- **Bag (cart):** tables `carts` (uuid id = the httpOnly `bag` cookie; optional `userId`) and `cart_items` (unique per cart + product + size, nulls not distinct). Server reads/merge in `src/lib/cart.ts` (`getBag()` returns lines with live price/stock and per-line `issue`s that block checkout; stock is per product and shared across sizes). Mutations are server actions in `src/app/bag/actions.ts` (`addToBag` via `useActionState` in `PurchasePanel`, `updateBagQuantity`, `removeFromBag`) that call `refresh()`. Cookie reads are dynamic, so bag UI (`BagLink` in the header, `/bag`, `/checkout`) renders inside `<Suspense>`. Client-safe types are in `src/lib/bag-types.ts`.
- **Checkout & orders:** Stripe Embedded Checkout (`ui_mode: "embedded_page"` in the installed SDK). `createCheckoutSession()` (`src/app/checkout/actions.ts`) re-validates the bag, cancels earlier pending orders for it, inserts a `pending` order + `order_items` snapshot (`src/lib/orders.ts`), and creates the session with DB prices. The webhook `src/app/api/stripe/webhook/route.ts` is the source of truth: `fulfillCheckoutSession()` flips pending→paid atomically (idempotent), decrements stock with guarded updates (sets `needsReview` if oversold), empties the bag, and calls `revalidateTag("products", { expire: 0 })`. `/checkout/complete` only displays. Use `getStripe()` from `src/lib/stripe.ts` (lazy, so builds don't need keys). Env: `STRIPE_SECRET_KEY`, `NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY`, `STRIPE_WEBHOOK_SECRET`, optional `STRIPE_AUTOMATIC_TAX=true` once Stripe Tax is set up. Local webhooks: `stripe listen --forward-to localhost:3000/api/stripe/webhook`.
- **Storefront:** `SiteHeader`/`SiteFooter` (`src/components/layout/`) wrap every page from `layout.tsx`. The header's `MenuDrawer` is a `<dialog>` side drawer used at every breakpoint; nav items with `children` (in `navigation`, `src/lib/catalog.ts`) open a second sliding panel. Shop sections are defined in `src/lib/departments.ts`: department sections (`womenSection`, `menSection`) list one department across categories, and category sections (`bagsSection`, `shoesSection`, `accessoriesSection`) list categories across departments. Each has filters (`new`, a category, or a department) and drives both the menu (`sectionNavItem` in `catalog.ts`) and its routes `src/app/<section>/page.tsx` + `src/app/<section>/[category]/page.tsx`, which just re-export `sectionRoute`/`sectionFilterRoute` from `src/components/listing/section-route.tsx` (products via `getSectionProducts()`, UI via `section-listing.tsx`). A new section is a `Section` object, a nav entry, and those two three-line route files. `categoryHref()` maps a DB category to its section page (`/bags`, or `/accessories/eyewear` for a grouped category); use it rather than building `/${slug}` links. New arrivals live at `/new` and `/new/[category]` (`new-arrivals-listing.tsx`), listing every `is_new` product newest first via `getNewArrivals()`. Both listings render through `ListingLayout` (`src/components/listing/listing-layout.tsx`: breadcrumb, title, sticky tabs, piece count, grid); new listing pages should use it too. The homepage's editorial content in `src/lib/catalog.ts` picks products by slug; products and the "Shop by category" tiles come from the DB. Product pages are `src/app/products/[slug]/page.tsx`, prerendered via `generateStaticParams`. With Cache Components on, `dynamicParams` isn't available, so unknown slugs render `not-found.tsx` with a 200 status plus `noindex`. Some links it renders (`/craft`, `/collections/...`, `/appointments`, `/search`) don't have routes yet.
- **Images:** `next.config.ts` uses a custom loader (`src/lib/image-loader.ts`) that has Unsplash's CDN do the resizing. A new remote image host needs handling there; `remotePatterns` alone won't do it.
- Path alias: `@/*` → `src/*`.

## Design system

All tokens and primitives live in `src/app/globals.css` and are shown on the `/design-system` page (`src/app/design-system/page.tsx`, noindex); update that page when you add or change a token (Tailwind v4, CSS-first; there is no `tailwind.config`). The look is monochrome luxury retail: photography supplies the colour, and the UI stays quiet.

- **Colours:** Tailwind's default palette is reset (`--color-*: initial`), so `zinc-*`, `gray-*`, etc. don't exist. Use the semantic tokens: `ink`, `ink-soft`, `ink-muted`, `ink-faint`, `paper`, `stone`, `stone-deep`, `line`, `line-strong`, `overlay`, `sale`, `success`, `accent`. `accent` (deep claret) is a signature mark for one editorial detail per view, never for controls, prices or states. The site is light-only.
- **Type:** `font-sans` (Geist) for UI and body text, `font-display` (Cormorant Garamond) for editorial headings. h1–h3 default to the display font. Sizes: `text-label`, `text-caption`, `text-body-sm`, `text-body`, `text-lead`, plus fluid `text-heading-sm`/`text-heading`/`text-heading-lg`/`text-display`. Use only weights 400/500. Uppercase tracked labels use `text-eyebrow`.
- **Geometry:** border radius is reset to zero, so `rounded-*` does nothing except `rounded-full` (for swatches only). Borders are 1px hairlines (`border-line`, `hairline`, `divider`).
- **Layout primitives:** `container-page` (1440px max, fluid `gutter`), `container-wide`, `container-prose`, `section` (fluid vertical rhythm), `product-grid` (2→3→4 columns), `product-media` (3:4 frame on stone), `hero-media` (4:5 → 16:9), `header-bar`. Spacing tokens: `p-gutter`, `py-section`, `h-header`.
- **Buttons/forms:** `btn` + `btn-primary` | `btn-secondary` | `btn-inverse` (over imagery), with `btn-block` for full width. `input-field` is a bottom-rule input.
- Breakpoints are Tailwind's defaults plus `xs` (480px, small vs. large phones) and `3xl` (1920px). Use the `sm:`/`md:`/`lg:` variants in markup and `@variant md { … }` inside `@utility` blocks; don't hand-write width media queries. Phone (< `md`) stacks editorial blocks; tablet (`md`) puts editorial pairs and the product page side by side; `lg` gets the larger header (sticky offsets switch from `--spacing-header` to `--spacing-header-lg` there).
